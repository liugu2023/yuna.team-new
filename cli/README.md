# yuna CLI

燕山大学大学生网络信息协会（YUNA）的命令行工具：在终端里看招新信息、文章、协会项目和授课计划，也能玩离线的数据包冒险。运行需要 Node.js 18.17 或更新版本。

本文对应 0.3.0。用 `yuna --version` 查看当前安装版本；npm 安装命令获取最新已发布版本，本地构建方式见下文。

## 使用

```bash
npx -y yuna-team@latest join  # 临时运行最新已发布版本
npm i -g yuna-team@latest     # 全局安装，之后直接使用 yuna
```

```bash
yuna join
yuna posts -n 5 --tag 运维
yuna read 1
yuna read docker-compose-in-lab
yuna projects --network public
yuna lesson --term 2026
yuna open recap
yuna play packet
```

| 命令 | 说明 |
| --- | --- |
| `yuna join` | 招新进行中显示报名信息；结束后显示收官情况、统计和后续参与入口 |
| `yuna posts` | 已发布文章列表，支持 `-n` 数量、`--tag` 标签、`--kind article\|knowledge`、`--all` 全部 |
| `yuna read <编号\|slug>` | 阅读文章；编号对应本站最近一次 `posts` 列表，`--web` 用浏览器打开 |
| `yuna projects [关键词]` | 项目目录，支持 `--network public\|internal\|unspecified`、`--status planning\|building\|maintaining\|archived` 和 `--tag` |
| `yuna lesson` | 最新届次课表；支持 `--term`、`--all` 全部届次、`-n` 每届课次上限、`--status planned\|completed\|cancelled` |
| `yuna open <页面\|路径\|地址>` | 在浏览器打开页面，支持 `recap`、`post:<slug>`、`page:<名字>` 等 |
| `yuna play packet` | 用键盘带数据包穿过网络的离线走迷宫小游戏，0.3.0 起提供，玩法见下文 |

全局参数：

- `--json`：输出 JSON。`open --json` 和 `read --web --json` 只输出地址，不启动浏览器。
- `--base <url>`：指定站点，默认 `https://www.yuna.team`；也可设置 `YUNA_API_BASE`。
- `--proxy <url>`：显式使用 HTTP(S) 代理，例如 `--proxy http://127.0.0.1:7890`。代理初始化或连接失败会报错，不会退回直连。
- `-h, --help` / `-v, --version`：帮助与版本。`yuna <命令> --help` 查看该命令用法。

离线 `play` 命令不接受 `--base` / `--proxy`，也不读取站点或代理环境配置。

未知参数、当前命令不支持的选项和冲突选项都会报错，例如 `yuna join --tag 运维`、`yuna posts --all -n 5`。成功退出码为 `0`，用法或接口错误为 `1`；错误写入 stderr。

## 数据包冒险

这是 0.3.0 新增的网络主题走迷宫小游戏，不需要先懂网络知识，术语后面会附上通俗解释。安装 0.3.0 或更新版本后运行：

```bash
yuna play packet                         # 随机地图
yuna play packet --seed yuna             # 固定练习地图
yuna play packet --seed yuna --json      # 离线查看固定地图数据
```

从源码运行时，在仓库根目录先构建：

```bash
npm run cli:build
node cli/bin/yuna.mjs play packet                         # 随机地图
node cli/bin/yuna.mjs play packet --seed yuna             # 固定练习地图
node cli/bin/yuna.mjs play packet --json                  # 只查看随机地图数据
```

**你控制的是数据包 `[]`。用方向键移动，先经过两个 `R` 路由（打卡点），先去哪个都行。两个都去过以后，再到 `G` 服务器（终点）就赢了。**

**TTL（体力）** 决定你还能走多远。普通一步扣 1 点，走进 `~~` 链路拥塞的格子，这一步总共扣 3 点，相当于遇到了更费体力的路。站着想路线不会扣 TTL，撞墙也不扣。TTL 不能补充，用完还没送达就输了；如果最后一步刚好用完，同时走进终点，也算赢。

**重传机会（护盾）** 是遇到丢包时的补救机会。每走进一次 `!!` 丢包格，用掉 1 次重传机会就能继续前进；没有机会时再遇到丢包，这局就结束了。机会用光后仍然能正常走路，只要避开丢包格。

上方状态栏会把本局情况分别写清楚：

| 显示内容 | 含义 |
| --- | --- |
| 地图种子 | 这张地图的名字，可用 `--seed` 再次打开同一张图 |
| TTL（体力）剩余 / 初始 | 现在还剩多少体力，以及这一局开局有多少；不是倒计时 |
| 重传（护盾）剩余次数 | 还能抵挡几次丢包，不是已经丢包的次数 |
| 路由已过 / 总数 | 已经经过几个 `R`，以及一共要经过几个 |
| 得分 / 已走步数 / 提示次数 | 本局拿到的分数、成功移动的格数，以及查看提示的次数 |
| 本图首次通关 | 本地没有这张地图的上次通关成绩可比较，不是说你第一次玩整个游戏 |

窗口较小时会用“余”表示剩余，完整的地图种子和初始 TTL 可在 `H` 帮助页查看。

| 地图上的符号 | 是什么 | 走到这里会怎样 |
| --- | --- | --- |
| `[]` | 数据包（你） | 方向键或 WASD 控制移动 |
| `█` | 墙 | 过不去，撞上不扣体力 |
| `R` / `r` | 路由（打卡点） | 两个都要去，每个加 100 分；去过后变成小写 `r` |
| `G?` / `G` | 服务器（终点） | 先经过两个路由；问号消失后走进去就赢了 |
| `~~` | 链路拥塞（更费体力） | 这一步扣 3 点 TTL |
| `!!` | 丢包（需要补救） | 用掉 1 次重传机会；没有机会时再遇到就输了 |
| `++` | 重传补给（加护盾） | 增加 1 次重传机会，最多存 3 次 |
| `**` | 缓存奖励（加分） | 加 50 分 |

红色是拥塞和丢包，绿色是补给和奖励。重传补给和缓存奖励只能拿一次；已经拿过的格子可以继续走。

| 按键 | 操作 |
| --- | --- |
| 方向键 / WASD | 移动 |
| T | 不知道往哪走时看提示，不扣 TTL（体力），也不扣分 |
| P / 空格 | 暂停 / 继续 |
| H / ? | 打开玩法说明，再按一次回到游戏 |
| R | 从头重玩这张地图；这是按键，别和地图里的打卡点混淆 |
| Enter | 一局结束后，再玩一次这张地图 |
| V | 一局结束后，切换成绩和传输复盘 |
| N | 换一张地图 |
| Esc | 关闭帮助、从复盘返回成绩、继续暂停；在游戏或成绩页退出 |
| Q | 退出 |

每次运行 `play packet` 都会随机生成一张地图，界面会显示这张图的名字。按 `R` 从头重玩当前地图，按 `N` 换图；想下次再玩同一张图，可以用 `--seed` 指定它的名字，例如 `--seed hello`。名字相同，地图就相同，也可以把名字发给同学比成绩。名字支持 1–64 个字符，`--seed yuna` 是固定练习图，其它名字会改变道路和打卡点的位置。

游戏会铺满终端窗口。放大、缩小窗口时，地图大小会跟着调整，位置和 TTL 不会变。如果提示窗口太小，把窗口拉大即可继续（至少 42 列 × 18 行）。不支持键盘交互的环境可以加 `--json`，只查看地图数据。

`T` 会给你一条避开丢包、比较省 TTL（体力）的路线，不一定能拿到最多分。看提示会记录次数，但不扣分；停在原地反复查看只算一次，撞墙后重看也不多算。没有可用提示时不计数，从头重玩后次数归零。

想多拿分，可以多收集 `**` 缓存奖励、少绕路、少经过丢包格。两个路由各加 100 分，每个缓存奖励加 50 分，成功送达再加 200 分。剩下的每点 TTL（体力）再加 5 分，每次重传机会（护盾）再加 20 分。一局结束后会显示总分、走了多少步、看了几次提示，以及比上次进步了多少。

结束后按 `V` 查看传输复盘：这一局经过了几次拥塞、因此比普通路额外消耗了多少 TTL、遇到了几次丢包，还有几个路由没经过。往返同一个格子会分别统计，撞墙不算；每次拥塞比普通移动多消耗 2 点 TTL。

服务器偶尔会给你一句特别的回信：刚好用完 TTL 时送达、收集全部缓存奖励，或者一路没有拥塞和丢包，都有对应的小彩蛋。游戏里还藏着一个本地回声回应。它们只增加趣味，不改分数，也不会真的发送网络请求。

成绩会自动保存在这台电脑上，退出后还在。成绩页会显示正在保存、保存成功或未保存的原因；保存没成功时，本局记录仍保留在当前游戏中，退出时会给出处理说明。每张地图分别记录最好成绩和上次通关成绩：先比谁的分高，同分时比谁走的步数少，再相同时比谁看的提示少。

成绩文件位于 CLI 缓存目录下的 `games/packet-v2/records.json`，可用 `YUNA_CACHE_DIR` 改变保存位置（默认目录见下文）。最多保留最近通关的 200 张地图，新旧规则的成绩分开保存。文件损坏时保留原文件；读取或写入失败不会中断游戏，退出时会说明。`--json` 和帮助命令不创建或改写成绩文件。

若进程被强制终止后一直无法保存，先关闭所有游戏进程，再移除同目录的 `records.json.lock` 后重试，保留 `records.json` 成绩文件。

游戏完全离线，不调用网站 API、不写线上数据。普通退出返回 `0`，Ctrl+C 返回 `130`。

## 文章编号与筛选

`posts` 默认显示 10 篇，`-n 60` 会跨接口分页读取 60 篇，`--all` 读取全部匹配文章，没有原先的 500 篇上限。`--tag` 对标签做不区分大小写的包含匹配，`--kind` 限定文章类型。

```bash
yuna posts --tag 运维 -n 5
yuna read 1                    # 刚才列表里的第 1 篇
yuna read 1 --tag 运维          # 重新查询当前运维筛选结果的第 1 篇
yuna read 2 --kind knowledge    # 当前资料列表的第 2 篇
yuna read 2026 --slug           # slug 为“2026”的文章，不按编号解释
yuna read 1 --web --json        # 只输出 { slug, url }
```

每次成功获取 `posts` 列表（包括 `--json`）都会保存编号到 slug 的本地快照。之后不带筛选的 `read 1` 使用这份快照，新发布文章不会把已有编号挤到另一篇。再次运行 `posts` 会替换本站快照；空列表也会清空旧编号。

第一次按编号阅读前需要先运行 `posts`。显式传入 `--tag` 或 `--kind` 时，`read` 改为查询当前筛选结果，不使用也不覆盖快照；这些筛选选项只用于编号查询，不能与 slug 阅读混用。正文始终从站点获取，快照不提供离线阅读。

快照按站点 `--base` 隔离，本地预览与线上列表不会互相覆盖。设置 `YUNA_CACHE_DIR` 可指定缓存目录；默认位置为：

| 系统 | 缓存目录 |
| --- | --- |
| Windows | `%LOCALAPPDATA%/yuna-team`，未设置时用用户目录下的 `AppData/Local/yuna-team` |
| macOS / Linux | `$XDG_CACHE_HOME/yuna-team`，未设置时用 `~/.cache/yuna-team` |

文章编号快照只保存站点地址与文章 slug。目录不可写时，`posts` 会提示并显示 slug，此时直接用 `read <slug>` 阅读；小游戏成绩使用上述缓存目录下独立的 `games/packet-v2/` 子目录。

## 招新与授课计划

`join` 与网站读取同一个 `recruitment-status` 开关。只有 `closed: true` 才按结束状态展示收官文案和四项统计，并给出收官、公开课、新成员指南与咨询入口；报名流程及旧报名入口会收起。缺失或损坏的开关默认按进行中处理，网络请求失败则明确报错。

`join --json` 保留 `title`、`lead`、`kpi`、`steps`、`contact`、`actions`、`url`，增加 `closed`、`recruitmentStatus`（`open` / `closed`）、`stats` 和 `recapUrl`。结束时 `kpi`、`steps` 为空数组，`contact` 是收官咨询文案；进行中 `stats` 为空数组，`recapUrl` 为 `null`。

`lesson` 优先按后台顺序展示届次，同序时按数字自然排序，例如第 10 届排在第 9 届前。课件的 `/media/...` 地址会转成完整地址，无标题链接用 URL 代替标题，邮件链接也会保留；普通输出与 JSON 使用相同链接数据。

## 数据来源

CLI 只读站点公开接口，不需要密钥，也不会写入线上数据：

- `GET /api/posts`、`GET /api/posts/:slug`：文章列表与正文。
- `GET /api/site?keys=…`：招新状态与可编辑文案、`association-projects` 项目目录、`lesson-plan` 课表。

招新文案缺失的字段使用网站内置文案。项目和课表没有记录时显示空状态。

网络访问优先使用运行时 `fetch`。遇到直连的连接超时或网络不可达时，GET/HEAD 请求会静默重试一次：等待 200ms，使用 `undici` 将每个地址的尝试时间设为 1000ms、连接超时设为 5 秒；请求和正文读取仍共享原有 15 秒总时限。HTTP 错误、证书错误、DNS 错误和已超时的请求不做这次重试。

CLI 不修改系统 DNS、不绑定固定网卡，也不会自行把 `HTTP_PROXY` / `HTTPS_PROXY` 环境变量作为备用出口。显式 `--proxy` 始终使用该代理，失败就报错；它影响 CLI 的 API 请求，浏览器仍使用自身的网络设置。`undici` 只在直连回退或显式代理时加载。

## 本地开发与测试

以下命令在仓库根目录执行：

```bash
npm ci
npm run cli:build      # 编译到 cli/dist
npm run cli:typecheck
npm run cli:test       # 编译并执行本地回归测试
npm run cli -- --help
```

本地联调先在另一个终端运行 `npm run dev`，再指定站点地址：

```bash
node cli/bin/yuna.mjs join --base http://127.0.0.1:8788
node cli/bin/yuna.mjs posts --base http://127.0.0.1:8788
node cli/bin/yuna.mjs read 1 --base http://127.0.0.1:8788
```

测试使用本地模拟接口覆盖分页、编号快照、招新状态、链接和错误处理，不依赖线上内容。

从 npm 包本地试装：

```bash
cd cli
npm pack                         # prepack 自动编译，产出 yuna-team-0.3.0.tgz
npm i -g ./yuna-team-0.3.0.tgz
yuna --version
yuna play packet --seed yuna --json
npm uninstall -g yuna-team
```

改动源码后重新构建才能运行；`npm pack` 和 `npm publish` 都会通过 `prepack` 自动构建。完整发布流程见仓库中的 `cli/PUBLISHING.md`，该文件不随 npm 包分发。
